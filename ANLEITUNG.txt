TINY WOO WEBSITE – ANLEITUNG (ORDNER-VERSION)
=============================================

1. HOCHLADEN AUF GITHUB (EINMALIG)
---------------------------------
1. ZIP entpacken (Rechtsklick -> "Alle extrahieren").
2. Den entpackten Ordner "website" öffnen.
3. Darin ALLES markieren (Strg + A).
4. github.com/RensbourroTaki/TinyWoo -> "Add file" -> "Upload files"
5. Alles ins Feld ziehen -> "Commit changes".
6. Settings -> Pages -> Source: "Deploy from a branch" -> Branch: main, / (root) -> Save
7. Nach 1–2 Minuten: https://rensbourrotaki.github.io/TinyWoo/

WICHTIG: index.html muss direkt neben README.md liegen, NICHT in einem Unterordner "website".
Falls eine alte index.html da ist: wird einfach überschrieben.


2. WAS IST WO?
--------------
   index.html            Die Seite. Nicht anfassen.
   inhalt.js             <-- HIER änderst du alles (Songs, Games, Links, Texte, Spiel)
   ANLEITUNG.txt         Diese Datei
   assets/logo/          tinywoo-logo.png
   assets/games/         Game-Bilder (rocket-trump-menu.jpg)
   assets/music/         OGGs für den Site-Player
   assets/daiganoid/     Grafiken + Sounds des Arcade-Spiels DAIGANOID (siehe Punkt 7)
   game/                 Der Spiel-Code von DAIGANOID (siehe game/README.md)
   game/filter/          Namensfilter der Highscore-Liste (Wortlisten in wordlist.js, siehe Punkt 8)
   api/                  Der Highscore-Server (Cloudflare Worker, siehe Punkt 8)
   fonts/                Schriften. Nicht anfassen.
   js/, tokens/, styles.css   Technik. Nicht anfassen.


3. ETWAS ÄNDERN (z.B. neuer Song)
--------------------------------
A) Datei hochladen
   - Auf GitHub in den Ordner gehen, z.B. assets -> music
   - "Add file" -> "Upload files" -> OGG reinziehen -> "Commit changes"

B) In inhalt.js eintragen
   - Auf GitHub inhalt.js anklicken
   - Rechts oben auf das STIFT-Symbol klicken
   - Zeile ergänzen, z.B. unter "musik":
       { title: 'Jungle Hangar', artist: 'Tiny Woo', src: 'assets/music/jungle-hangar.ogg', duration: 201 },
   - Oben rechts "Commit changes" -> nochmal "Commit changes"

C) 1–2 Minuten warten, Seite neu laden (Strg + F5).


4. DIE WICHTIGSTEN STELLEN IN inhalt.js
--------------------------------------
   links.email     -> Kontakt-Adresse, getrennt in ['name', 'domain'] (Press-Seite, Spam-Schutz)
   links.kontaktFormKey -> Web3Forms-Key fürs Kontaktformular (About-Seite)
   socials         -> Social-Buttons. href = Link. Zeile löschen = Button weg.
   musik           -> Playlist. Reihenfolge = Reihenfolge im Player.
   games           -> Games. featured: true = groß auf der Startseite.
                      trailer = YouTube-Link, presse = Fakten + Screenshots.
   presse          -> Press-Seite: Intro, Studio-Fakten, Downloads.
   daiganoid       -> Arcade-Spiel: Titel, Text auf der Startseite, Musik (OGG-Pfade),
                      apiUrl (Highscore-Server), header (Kopf der Arcade-Seite),
                      story (Text links neben dem Spiel), highscoreTitel, storyTitel.
   texte           -> Überschrift, Texte, Laufband, Footer.

Alles in inhalt.js ist kommentiert. Beispiele stehen direkt dabei.


5. TIPPS GEGEN FEHLER
--------------------
   - Texte immer in 'einfachen Anführungszeichen'.
   - Hinter jedem Eintrag ein Komma.
   - Apostroph im Text (z.B. don't)? Dann den Text in "doppelte" Anführungszeichen setzen.
   - Dateinamen klein, ohne Leerzeichen/Umlaute: jungle-hangar.mp3
   - Pfad in inhalt.js muss EXAKT zum Dateinamen passen (auch Groß/Klein!).
   - Seite plötzlich leer? Dann ist in inhalt.js ein Komma/Anführungszeichen kaputt.
     Auf GitHub -> inhalt.js -> "History" -> letzte Version wiederherstellen,
     oder schick mir die Datei.


6. HIGHSCORES
------------
   Die Liste rechts neben dem Spiel und die Liste im Spiel sind dieselbe: sie kommt vom
   Highscore-Server (Punkt 8). Im Spiel stehen die Top 10, auf der Seite bis zu Top 100.
   Eintragen geht nur nach einem echten Game Over. Namen: max. 10 Zeichen, A-Z 0-9 und . , ! ?
   (mehr kann die Drehschrift nicht), und sie laufen durch den Wortfilter: Schimpfwörter,
   Beleidigungen, Sex, Hass, Drogen, Links usw. werden gar nicht erst gespeichert.
   Ist der Server nicht erreichbar (oder apiUrl in inhalt.js leer), sieht jeder nur seine
   eigene, im Browser gespeicherte Liste.


7. DAIGANOID (ARCADE-SEITE)
---------------------------
   Das Spiel läuft komplett im Browser, ohne Build. Steuerung: Maus (Klick = Mauszeiger wird
   "eingefangen" wie ein Arcade-Spinner, Esc gibt ihn frei), Pfeiltasten/A-D, Touch.
   Feuer = Klick/Leertaste. P = Pause. Vollbild-Knopf unter dem Spiel.

   Grafiken austauschen: assets/daiganoid/... (PNG mit Transparenz, Animationen als senkrechte
   Streifen, Frame unter Frame). Maße und Namen stehen in game/render/assets.js.
   Noch als Platzhalter (werden automatisch benutzt, sobald die Datei da ist):
     assets/daiganoid/menu/logo.png              Logo 237x65
     assets/daiganoid/player/paddle-laser.png    Laser-Schläger, 2 Frames 34x9 (wie paddle-thrust.png)
     assets/daiganoid/player/paddle-catch.png    Magnet-Schläger, 2 Frames 34x9
     assets/daiganoid/player/laser-shot.png      Laserschuss

   Hintergründe: assets/daiganoid/board/bg01.png, bg02.png, bg03.png ... (fortlaufend nummeriert,
   das Spiel lädt bis zur ersten fehlenden Nummer; neues Bild ablegen genügt). Runde 1 = bg01,
   danach reihum bg02 bis zum letzten. Vollbilder haben 240x334 (= Spielauflösung) und werden
   nicht wiederholt; kleine Bilder (Kacheln) werden ab links oben über den Schirm wiederholt.
   Schimmer: liegt daneben bgNN_mask.png (schwarz/weiß, gleiche Größe), fließt auf den weißen
   Stellen Strom im Farbton des Hintergrunds. Regler: game/render/bgfx.js (BGFX).

   Musik: OGG nach assets/daiganoid/music/ hochladen, Pfade in inhalt.js unter "daiganoid" eintragen.
   Menü: "Out There" von yd, Highscore: "Party Sector" von Joth (beide OpenGameArt, CC0, in den Credits genannt).
   Lautstärke im Spiel: Optionen -> MUSIC (OFF, 1-10).

   Level: game/play/levels.js, 32 Runden mit je zwei Varianten (linkes/rechtes Portal),
   Textzeilen mit 11 Zeichen, Legende steht oben in der Datei.
   Level-Namen (Ansage "LEVEL 01", dann der Name): game/play/levelnames.js, je 32 links und rechts.

   Test-Tasten (Schalter DEV_KEYS oben in game/app.js, auf false stellen = aus):
   Pfeil links/rechts = Level wechseln (Spiel startet neu), Pfeil hoch = God Mode an/aus.
   Solange an, lenkt man mit Maus oder A/D statt mit den Pfeiltasten.

   Lokal testen (Module brauchen einen Server): im Ordner "python -m http.server 8765",
   dann http://localhost:8765/#arcade öffnen.


8. HIGHSCORE-SERVER (CLOUDFLARE WORKER)
--------------------------------------
   Der Server ist ein kleines Programm bei Cloudflare (kostenlos), Code im Ordner api/.
   Er speichert die gemeinsame Highscore-Liste, prüft jeden Namen mit dem Wortfilter,
   bremst Spam (1 Eintrag je 15 s und IP) und zählt, wer gerade auf der Arcade-Seite ist
   ("3 online · 1 playing" über der Liste).

   Adresse: steht in inhalt.js unter daiganoid.apiUrl.
   Admin-Schlüssel: E:\MY-PROJECTS_2019\TINY_WOO\daiganoid-admin-key.txt (NICHT ins Repo!)

   Einträge ansehen und löschen (Adresse + Schlüssel einsetzen, im Browser öffnen):
     ADRESSE/admin/scores?key=SCHLÜSSEL                  alle Einträge mit Nummer (id) und IP-Kennung
     ADRESSE/admin/delete?key=SCHLÜSSEL&id=12            Eintrag Nr. 12 löschen
     ADRESSE/admin/delete?key=SCHLÜSSEL&name=XYZ         alle Einträge mit diesem Namen löschen
     ADRESSE/admin/delete?key=SCHLÜSSEL&ip=KENNUNG       alle Einträge dieser IP-Kennung löschen
     ADRESSE/check?name=TESTNAME                         Filter ausprobieren (ohne Schlüssel)

   Wortfilter erweitern: game/filter/wordlist.js (kommentiert, nach Gruppen sortiert). Danach
   1. Website hochladen (Commit), damit die Eingabe im Browser das Wort kennt, und
   2. den Server neu hochladen, damit er es auch kennt:
        Konsole (PowerShell) im Ordner api/ öffnen:  npx wrangler deploy
      (Beim ersten Mal auf einem neuen Rechner vorher:  npx wrangler login)

   Erlaubte Seiten (CORS) stehen in api/wrangler.jsonc unter ALLOWED_ORIGINS. Zieht die Website
   auf eine andere Adresse um, dort ergänzen und neu deployen.
